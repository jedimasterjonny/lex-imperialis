# fleet

Not a role — it runs on no host and renders nothing. A container for the
composed-fleet scenario, which stands each host's real roles up together on one
instance and checks they work as a set.

`bin/check-role-test-coverage.sh` requires a `molecule/default` or
`molecule/libvirt` scenario per directory under `roles/`, and the make targets
reach a scenario only at
`roles/<name>/molecule/`, so the harness lives here. A layout constraint, not a
claim that this is a role — worth relocating whenever that coverage contract is
reworked.

## What it tests

Every other scenario proves a role works **alone**. Nothing proved they work
**together**, and `CLAUDE.md` says so outright in the handler-naming convention:
*"molecule misses it — the role runs alone."* That is the repo documenting a bug
class its harness is blind to, then patching the hole with a prose rule.

The converge is most of the test. Eleven roles on solar, nine on rogue-trader, in
production order, on one instance — which exercises what a single-role converge
cannot: handler names colliding across roles, role ordering, and shared
directories one role creates and another needs. molecule's idempotence check
covers the second run.

`verify.yml` adds the two things a converge cannot state for itself:

- **The podman named-volume set, by name.** The restic repo is keyed on these, so
  a rename orphans its backing store while still rendering a valid quadlet and
  starting a healthy container. The one data-loss surface here, and nothing else
  covers it.
- **The secret-dependent template branches, on their production arm.** Eight
  branches, 12 assertions — the `arr` `EnvironmentFile` branch is checked once per
  app, and `acme_dns` on both hosts. Without them the converge could pass having
  exercised the empty arm of every one: a green run over code paths production
  never takes.

## Instances

| Instance | Roles |
| --- | --- |
| solar | `podman`, `autoupdate`, `caddy`, `grafana`, `homepage`, `arr`, `podman_backup`, `home_backup`, `node_exporter`, `cadvisor`, `alertmanager` |
| rogue-trader | `wireguard_client`, `podman`, `autoupdate`, `caddy`, `wordpress`, `podman_backup`, `home_backup`, `node_exporter`, `cadvisor` |

Each is its host's production role list minus the roles with nothing to compose, in
the play's order, held to it by `bin/gen-fixture-hostvars.py` rather than by
review. `podman` must come first — it creates `/etc/containers/systemd`, without
which the converge dies on the first quadlet.

These are the two shapes this can host. `scholam` would add exactly one role it
does not already compose — `gitops_reconcile`, whose three operator-placed secret
files need a fourth prepare stub — so it is worth adding only if that role's
composition starts mattering. `administratum` cannot be hosted at all: it is the
Synology, `become: false`, running three docker-compose roles, and the only image
here is Tumbleweed.

### Excluded roles

`common`, `sshd`, `firewalld` and `nfs` — nothing to compose, and their own
scenarios cover them. That list is `EXCLUDED_ROLES` in the generator, and holds
only what these two plays actually contain: a role in a play that is neither
excluded nor converged fails `check_roles` loudly.

## Fixtures

`inventory/group_vars/<group>.yml` is generated by `bin/gen-fixture-hostvars.py`
from `inventory/host_vars/<host>.yml`, verbatim — nothing else, and a play that
carries variables in any form fails the run (`bin/README.md`). A pre-commit
hook regenerates and fails on drift, so the converge runs against the host's real
variables and the fixture can never become a second source of truth. Never
hand-edit one. The same hook holds `converge.yml`'s role list to the play's.

`inventory/group_vars/all.yml` is the hand-written stand-in for the vault, which
molecule cannot decrypt. Ansible resolves it *beneath* the per-group files by its
own precedence, so the per-group file always wins — the same ordering production
has, where a host's own declaration outranks a vault var from `group_vars/all`. Nothing
merges it; that is why it is a separate file rather than something the generator
folds in.

They are **group_vars reached through a second `-i` inventory source**, not
`provisioner.inventory.host_vars`. That key takes an inline dict and cannot
reference a generated file, and molecule names instances with
`${MOLECULE_RUN_ID}`, so no file could be named for a host. Group names are
stable. This still lands in inventory scope, which is what `hostvars[...]` reads.
`provisioner.inventory.links` is barred: setting *any* `links` entry silently
drops *all* inline `group_vars`, stripping `ansible_connection` from
`molecule/incus/base.yml`.

### Dummy secrets

Empty vault placeholders are not a neutral default. `restic_backup` asserts a
non-empty password, so the converge would not run at all; and the eight branches
above take their absent arm on an empty secret, so a converge with hollow secrets
would prove nothing about the code production runs.

Three things in `inventory/group_vars/all.yml` look like oversights and are not:

- **`arr_wireguard_conf` stays empty.** A structurally valid value renders
  `HealthOnFailure=kill` on a tunnel that can never answer its `HealthCmd`,
  because the dummy endpoint is TEST-NET. wireguard's `NRestarts` then climbs
  every ~90s and each restart cycles the six `PartOf=` joiners, permanently.
- **`grafana_admin_password` is not dummied.** Nothing in the repo sets it, so
  production renders `/etc/grafana/env` empty. The empty arm *is* production's.
- **`caddy_domain` is not dummied.** Its role default `home.arpa` flips no branch,
  and the real apex has no business in a public repo.

## Prepare

Three stubs, none optional. Each stands in for state a real host has and no role
in the converge creates. **Adding one is a review-blocking change** — a stub that
pre-creates what a role should create masks the failure it hides.

1. **The host's wireguard module.** solar converges `arr` with wireguard enabled,
   and that container drives the host's kernel module. An unprivileged instance
   cannot autoload it and the image ships no kmod. Invisible on a workstation that
   already runs WireGuard; only bites on a clean runner.
2. **rogue-trader's exporter bind address.** `node_exporter` and `cadvisor` bind
   the address they are given, and rogue-trader's `host_vars` carries a literal
   WireGuard address that exists only once the tunnel is up — without it
   node-exporter hits its start limit and cadvisor restart-loops. solar needs
   nothing: its address derives from a gathered fact, so it binds one the container
   holds.
3. **arr's NFS bind sources.** solar sets `arr_data_dirs: {}` because the NAS owns
   the layout, so nothing creates them, and podman will not create a missing bind
   source.

`wordpress-cron.service` fails on rogue-trader — *"The site you have requested is
not installed"* — because the timer fires against an uninstalled WordPress. The
converge stays green; an assertion of "no failed units" would not.

## Running it

```console
make converge ROLE=fleet     # both instances
make verify   ROLE=fleet     # the volume and branch assertions
make test     ROLE=fleet     # full lifecycle, including the idempotence check
make destroy  ROLE=fleet

make render-drift BASE=main  # converge both sides, diff what they rendered
```

`make test ROLE=fleet` is **11–13 minutes** for two instances, nearly all of it
container image pulls. The whole CI job — checkout and `incus admin init` included
— has run in **10m46s and 13m33s** on identical trees, against its
`timeout-minutes: 20`. Budget from the slower figure and note the spread before
adding a third shape: a timeout resolves to `cancelled`, which `molecule-gate`
turns into a red required check.

`make render-drift` converges both sides: **~16 min**, halving to ~8 when CI
restores the base side from cache. Its `timeout-minutes: 45` is sized for the
runner, not the converge — `Set up incus` has measured 13s and 876s on different
runs, and the slow one alone took a normal run to 31 min. Do not trim it.

## Known gaps

- **No instance is named for a host.** Instances are
  `lex-fleet-<shape>-incus-${MOLECULE_RUN_ID}` in *groups* `solar`/`rogue_trader`, so
  there is no host `solar` here. The fixture is a verbatim projection, so the first
  `hostvars['<other host>'][…]` to appear in one of these two hosts' variables converges
  against a host that does not exist and dies undefined. Reading solar's data *from
  administratum* is safe — administratum is not converged here at all, though solar's
  two fact-templated values resolve there only because `site.yml` imports solar first.
- **The converge itself does not gate rendered bytes** — that is now
  `bin/check-render-drift.py`'s job, which converges this scenario on a base ref
  as well and diffs the artefact roots (see `bin/README.md`). A byte-exact golden
  was built and dropped rather than shipped: it gates unintended *change*, while
  the drift this repo has actually had was omission-on-addition (`477b6d0`,
  `3570ebb`, `92d6443`) or handler-only (`e2937a3`) — none of which a golden
  fails. The differential check answers the other question, whether a refactor
  moved a byte, without a baseline to keep.
  **Its two limits are this scenario's limits.** It sees solar and rogue-trader
  only, so the templates `restic_backup`, `gitops_reconcile`, `incus`, `libvirt`,
  `prometheus`, `blackbox_exporter`, `common`, `dev` and `docker_prune` render are
  gated by nothing; and it compares head against base, so it catches a change a PR
  makes, never a render that was always wrong.
- **The scenario's own CI trigger and its value are still disjoint.** `discover`
  maps a changed path to that role alone, so renaming a handler in `roles/caddy/`
  runs nothing here — the exact bug class this exists for. Editing a host's
  variables *does* run it, because the hook regenerates a fixture under this
  directory, and that is the case with no composition risk. Wiring the rest in was
  tried and dropped: ~13 min on roughly 45% of commits is a poor trade. Treat this
  as a manual pre-merge tool and the CI run as incidental — run it by hand when
  composing behaviour changes: role order, a handler name, a directory one role
  creates for another.
  The `render-drift` job is a separate trade with its own trigger, derived from
  which roles template into a watched root — 24% of the last 120 merges.
- **The handler-collision class is exercised, not observed.** Running the roles
  together makes a collision *possible*; nothing here detects one unless it stops
  a container starting.
- **Environment-conditional renders never fire.** `roles/podman/tasks/main.yml`
  renders `/etc/NetworkManager/conf.d/podman.conf` only `when`
  `/etc/NetworkManager/conf.d` exists, and no NetworkManager is installed in the
  container. It is the drop-in that stops an NM event unmounting NFS
  mid-`podman_backup`.
